# BeanShell debugger fixtures

Fixtures for validating debugger hook points in BeanShell 2.0b6. Each file targets
one specific execution path, so when a hook misbehaves you know which path broke.

Breakpoint markers are comments of the form `// BP:n` — grep for them instead of
relying on line numbers, which drift.

Nothing here ships. `DebugHost.java` is a Gradle source set purely so it is compiled
by every build and cannot rot against a BeanShell upgrade unnoticed.

## Running them

```bash
./gradlew :agent:samples:runScript -Pscript=01_basic.bsh   # via Interpreter.run()
./gradlew :agent:samples:runHost                           # via Interpreter.eval(), 8 scenarios
./gradlew :agent:samples:runHostWithAgent                  # the same, instrumented
```

**Run both entry points.** `run()` and `eval()` are two separate loops
(`Interpreter.java:471` and `Interpreter.java:659`). An agent that hooks only one
appears to work in the CLI and does nothing in an embedded library, or the reverse.

### Checking that the agent changes nothing

`runHost` and `runHostWithAgent` must produce the same output, after normalizing
three things that legitimately differ:

```bash
norm() { grep -v "OpenJDK 64-Bit Server VM warning" "$1" | sed -E 's/@[0-9a-f]{6,}/@HASH/g' | sort; }
diff <(norm plain.txt) <(norm agent.txt)
```

- The **JVM warning** about class-data sharing appears because the agent appends the
  hook jar to the bootstrap classpath. Unavoidable and harmless.
- **Identity hash codes** shift deterministically — initializing the hook on the
  interpreter thread advances that thread's identity-hash sequence. See
  "Not bit-transparent" in [`agent/README.md`](../README.md).
- **Thread interleaving** in `06_callbacks_threads.bsh` varies between runs *without*
  the agent too, so the output has to be sorted before comparing.

## Files

| File                                    | Covers                                      | Watch out for                                                        |
|-----------------------------------------|---------------------------------------------|----------------------------------------------------------------------|
| `01_basic.bsh`                          | top-level statements, loops, block scoping  | statements in loop bodies do **not** re-enter the `Interpreter` loop |
| `02_methods.bsh`                        | frames, recursion, `synchronized`, `throws` | redefinition does not replace — see the defects note below           |
| `03_invocation_forms.bsh`               | the three call forms                        | group C never touches `Name`                                         |
| `04_closures.bsh`                       | `This`, closures, scope chain               | variables live in *parent* namespaces, not one flat frame            |
| `05_scripted_class.bsh`                 | generated bytecode + shim                   | constructors must be `public` — see the defects note below           |
| `06_callbacks_threads.bsh`              | proxies, threads, Java→script               | outermost frame has line `-1`                                        |
| `07_eval_and_source.bsh` + `07_aux.bsh` | `source()` vs `eval()` identity             | `eval()` reparses every call                                         |
| `08_exceptions.bsh`                     | TargetError / EvalError / parse error       | `finally` eats return values — see the defects note below            |
| `DebugHost.java`                        | 8 embedded scenarios                        | the realistic third-party-library entry pattern                      |

## Three BeanShell defects these confirmed

Writing the fixtures isolated three real bugs in BeanShell 2.0b6, each of which
affects a debugger specifically. They are recorded in
[`docs/BEANSHELL-DEFECTS.md`](../../docs/BEANSHELL-DEFECTS.md), with the fixture
that demonstrates each one. None is caused by the fixtures.

## Notes on what is deliberately not here

- **Uncaught script exception** — commented out at the end of `08_exceptions.bsh`,
  since it aborts the run.
- **Compiled Java command (`dir`)** — commented out in `03_invocation_forms.bsh`,
  since it prints a directory listing. Uncomment to exercise
  `Reflect.invokeCompiledCommand`.
- **Varargs and Project Coin syntax** (try-with-resources, diamond) — unsupported
  in 2.0b6 and part of the known JUnit failure baseline. Not usable as fixtures.
